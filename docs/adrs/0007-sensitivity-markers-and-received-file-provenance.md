# ADR 0007: Clipboard sensitivity markers and received-file provenance

Status: Proposed
Date: 2026-11-12
Owner: Product owner
Decision IDs: D-032, D-033 (PROPOSED). Related: PR-024, D-019 (OPEN), NFR-002

## Context and evidence

**Sensitivity markers.** Platforms and applications provide hints that clipboard content should not be recorded or synced:

| Platform | Markers | Evidence |
|---|---|---|
| Windows | `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory`, `CanUploadToCloudClipboard` | [V] |
| macOS | `org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType` | [V, community convention] |
| Android | `ClipDescription.EXTRA_IS_SENSITIVE` | [V] |
| iOS (write side) | `localOnly`, `expirationDate` | [K] |

Promoting a OneCopy item to the OS clipboard can expose it to OS and keyboard-app clipboard histories and to vendor cloud sync.

**Provenance.** Files received from another device carry no "came from elsewhere" marking unless one is applied:

- **Windows.** Mark-of-the-Web is the `Zone.Identifier` alternate data stream. `IAttachmentExecute::Save` "may attach evidence … in its NTFS alternate data stream" and "may run virus scanners" [V]. Alternate data streams do not survive FAT32 or exFAT.
- **macOS.** `com.apple.quarantine` is set through `NSURLQuarantinePropertiesKey` or the `LSFileQuarantineEnabled` Info.plist key [V/S].
- **Linux.** No OS-enforced equivalent; freedesktop `user.xdg.origin.*` extended attributes are informational only [K].
- **Android and iOS.** No direct equivalent [K].

## Decision (proposed)

1. **Capture (D-032).**
   - Treat content carrying an exclusion or concealed marker as **excluded** from capture and sync by default.
   - Treat `AutoGeneratedType` as "skip by default".
   - Record only the fact that an item was excluded, never its content.
2. **Promotion (D-032).** When promoting an item that is sensitive (marked at origin or by user policy), set the platform's markers:
   - Windows: the exclusion formats;
   - macOS: concealed plus transient;
   - Android: `EXTRA_IS_SENSITIVE`;
   - iOS: `localOnly` plus an expiry.

   This keeps OS histories and cloud clipboards from retaining it, where the OS honors the markers.
3. **Limitations, documented and shown in UX copy.**
   - Markers are voluntary and set by the source application. Their absence does not mean the content is not sensitive.
   - Some apps set no markers.
   - OS and keyboard-app behavior with markers varies by version.
   - Apps can misuse markers to hide content.
   - On Android, OneCopy can see the marker only when it is allowed to read the clip.
4. **Provenance (D-033).**
   - Managed downloads apply the platform's provenance mechanism where one exists: Windows Mark-of-the-Web, preferably through `IAttachmentExecute`; macOS quarantine.
   - Native-paste provenance is **observed**, not assumed (E-02, E-03).
   - The exact mechanism and the Zone ID or quarantine attributes are fixed after research and measurement.
   - Never preserve setuid or setgid bits. Executable-bit handling is a separate policy item.

## Alternatives considered

- **Ignore markers.** Leaks password-manager content.
- **Treat all content as sensitive.** Makes the product unusable.
- **No provenance marking.** Cross-device executables and documents would bypass OS safety prompts.

## Security/privacy and interoperability effects

- Provenance marking may trigger antivirus scans and SmartScreen, Gatekeeper or Protected View prompts. That friction is the intended security effect.
- Markers reduce leakage only where the OS honors them.

## User/product effects

- Some items never appear in OneCopy history; the UI says why ("excluded by the app that copied it").
- Received executables can show OS warnings.

## Consequences and follow-up tests

- E-01, E-03 and E-04 test capture and promotion marker behavior.
- E-02 records `Zone.Identifier` on pasted files.
- The managed-download provenance implementation is tested in E-09 on Windows.
